# Backend directory map

This file records which parts of the backend are maintained by hand and which
parts are produced by generators.

Legend:

- `[M]` maintained manually
- `[API]` generated by `goctl api go` from an `.api` contract
- `[RPC]` generated by `goctl rpc protoc`/`protoc` from a `.proto` contract
- `[DB]` generated by `goctl model` from a MySQL table or checked-in `.sql` DDL
- `[C]` manually maintained constants

## Generator boundary

Do not hand-create or hand-copy generator-owned output. In particular:

- API output: service entrypoints, `internal/config`, `handler`, `logic`,
  `svc`, `types/types.go`, and `handler/routes.go`.
- RPC output: protobuf Go files, RPC clients, servers, service contexts, and
  method logic scaffolds.
- Model output: `*_gen.go`, generated query interfaces/structs, and model
  scaffolds. Extend only the generator-designated safe-to-edit files after
  generation.

The screenshot calls the friend-application model `friend_application`; the
reference implementation uses `apply_friend`. This scaffold follows the
reference implementation so later imports and table names stay consistent.

## MySQL boundary

The checked-in `.sql` files are schema inputs, not MySQL runtime data files.
MySQL creates its own tables and physical data after these DDL files are
completed and applied. Runtime files such as InnoDB tablespaces, binlogs, and
container volumes must not be committed.
